# Settings & Account 2.0 — accepted scope, staged delivery
Stage 1: seven cards and native accessible modal, isolated CSS, server-derived roles, current login/logout and existing consent controls. No new personal data storage, no payment mutation. Approved visual direction: navy, cyan/purple gradient borders, gold Premium accents, blurred backdrop, responsive cards. CSS mockup is not yet screenshot-verified against the approved render.
Stage 2: verified profile email (only for authorized own account), durable profile/preferences, account creation date, PL/EN translations, timezone/date/window/market/venue settings. Avoid profile photo uploads initially; dark theme only.
Stage 3: Stripe sandbox verified subscription lifecycle and account-mapped customer portal, history/renewal from canonical evidence only. No live checkout or production rollout without explicit approval.
Stage 4 (accepted product roadmap): in-app notifications for favorite teams, followed players, verified injury status changes, fixture reminders/results and release updates; later email and push. Design opt-in per category, delivery deduplication, timezone-aware scheduling, verified evidence, rate limits, unsubscribe, privacy and retention. No active switches or claims of delivery until implemented and tested.
Privacy: preserve existing notice/version/epoch/receipt and withdrawal gates. Publish approved policy before activation. Data requests are human-reviewed via contact mailbox; no fake seven-day promise.
Security: use verified Google OIDC; do not present local password or 2FA management, remote session list, or GitHub linking as supported. Admin only sees own role; server entitlement rules unchanged.
Release: dedicated branch, desktop/mobile browser QA, verify against approved screenshots, review overlapping PR189 changes before integration. No production deployment, database writes, migrations, or secret edits.
